# Effect typegen example

Typed [Effect](https://effect.website) v4 schemas from `.surql`, with no
database anywhere in the build.

```text
database/schema/001_app.surql      the schema (the only thing you edit)
surrealkit.toml                    [typegen] json + [typegen.emit.effect]
src/generated/schema.json          schema document v2 (generated)
src/generated/surreal/*.ts         Effect modules (generated by effect-surrealkit)
src/app.ts                         code using them; its @ts-expect-error lines are
                                   mistakes the generated types reject
```

`surrealkit compile` applies the schema to a throwaway in-memory engine, writes
the schema document, and runs `effect-surrealkit` as an
[external emitter](../../docs/typegen/external-emitters.md); SurrealKit writes the
modules atomically and records them in `src/generated/surreal/.surrealkit-emit.json`.

```bash
npm install --no-package-lock      # effect-surrealkit comes from ../../packages (build it first)
npm run generate                   # surrealkit compile
npm run check                      # CI: fail if the committed generated files are stale
npm run typecheck                  # tsc --noEmit, strict + exactOptionalPropertyTypes
```

`surrealkit` must be on `PATH` (`cargo install surrealkit`, or the workspace's
`target/debug`). In this repository CI regenerates the files and runs the
typecheck, so a change to SurrealKit or to the emitter that changes the
generated code fails until the committed files are regenerated.

The generated files also record the versions that produced them (the SurrealKit
version, commit and engine version in `schema.json` and `manifest.ts`, the
emitter version in `manifest.ts`). `npm run check` compares bytes, so in a
project that pins its tools, regenerate as part of the change that bumps them.
This repository's CI ignores only those version lines, so a SurrealKit or
`effect-surrealkit` release, or a bump of the `surrealdb` crate, does not need
the example regenerated unless what it generates changes.
